# ETRI 0.5 µm 디지털 칩 설계 리포지토리의 최종 목표

이 문서는 만들고자 하는 결과와 지원 범위·완료 기준을 정의한다. 실행 순서와 진행 상태는 [ROADMAP.md](ROADMAP.md)에서 관리한다.

## 1. 목표

처음 사용하는 사람이 README에서 시작해 오픈소스 EDA 도구를 준비하고, 프로젝트를 생성한 뒤 다섯 단계의 튜토리얼을 따라 자신의 디지털 RTL을 합성·배치배선·검증할 수 있는 리포지토리를 만든다.

사용자는 생성된 YAML의 빈칸을 안내에 따라 채운다. 사람과 AI agent는 같은 설정·실행 명령·검증 결과를 사용하며, AI 없이도 전체 흐름을 진행할 수 있어야 한다.

기준 예제는 **`shift_reg_8bit`**, 확장 예제는 **FIR**다. 두 예제와 사용자의 새 설계가 같은 공통 흐름을 사용한다.

## 2. 최종 사용자 흐름

1. README에서 지원 환경·설계 범위를 확인하고 필요한 도구를 설치·점검한다.
2. ETRI 제공 PDK 경로를 지정하고 독립된 프로젝트를 생성한다.
3. 생성된 RTL/TB 틀과 YAML 양식의 필요한 빈칸을 작성한다.
4. **Synthesis 준비 → Synthesis·PRE-STA → Auto P&R 준비 → Auto P&R → POST-STA·최종 검증**을 순서대로 수행한다.
5. 단계별 통과 여부·로그·다음 행동을 확인하고, 자기 RTL과 제약으로 같은 흐름을 재실행한다.

## 3. 제공할 결과

| 결과 | 사용자가 할 수 있어야 하는 일 |
| --- | --- |
| 설치·점검 안내와 자동화 | README만으로 지원 도구를 준비하고 환경·PDK의 문제를 확인한다. |
| 프로젝트 생성기와 입력 양식 | 기존 파일을 덮어쓰지 않고 프로젝트를 만들며, YAML 구조를 새로 설계하지 않고 빈칸을 채운다. |
| 다섯 단계 튜토리얼과 실행 코드 | 원리·입력·명령·예상 결과·통과 기준·실패 복구를 따라 각 단계를 수행한다. |
| 예제와 자동 판정 | 기준 예제에서 시작해 FIR와 자기 설계로 확장하고 기능·타이밍·물리 결과를 확인한다. |
| 재현 가능한 산출물 | RTL·제약·PDK·도구 식별과 netlist·GDS·보고서를 연결해 같은 설계를 다시 실행한다. |
| 재사용할 조언과 선택 AI 안내 | 검증된 lessons를 찾고, 필요한 상황에서 복사 가능한 프롬프트와 작성 시점에 확인한 모델·effort 안내를 사용한다. |

## 4. 지원 범위와 원칙

첫 지원 대상은 **Ubuntu 24.04 LTS x86_64 CLI에서 실행하는 표준셀 기반 디지털 코어 흐름**이다. 단일 상승 에지 클록·단일 5 V 전원·제공 TT Liberty 범위에서 시작한다. 예제의 클록·리셋·I/O 조건은 명시하고 설계별 의도를 입력받는다.

아날로그 설계, HLS, FPGA/보드 실습과 다중 클록·매크로·복잡한 DFT는 최초 지원 범위에서 제외한다. 코어 완료와 실제 칩의 pad ring·IO/ESD·실링링·제출 완료를 구분한다.

EDA 실행은 오픈소스 도구를 사용한다. ETRI 제공 PDK 원본은 보존하고 필요한 view·규칙·모델을 참조하며, 파생 변환과 검증 근거를 식별한다. 제공된 자료를 활용해 중복 준비를 줄인다.

기능·타이밍 의도를 임의로 완화하거나 미실행·미검증 항목을 통과로 표시하지 않는다. 필수 배선 RC와 선택 트랜지스터 PEX를 구분하고 검증 범위를 공개한다.

## 5. 목표의 완료 기준

- 지원 환경에서 README를 따라 설치·점검·프로젝트 생성을 재현할 수 있다.
- 사용자가 양식과 튜토리얼만으로 필요한 입력을 작성하고 다섯 단계를 실행할 수 있다.
- RTL·합성 후·P&R 후 기능검증, PRE/POST-STA, CTS·배선 RC·GDS·최종 DRC/LVS 등 지원 범위의 필수 검증이 실제 실행되어 판정된다.
- 단계별 산출물이 일관되게 인계되고 입력 변경 후 필요한 단계만 다시 실행되며 오래된 결과가 통과로 재사용되지 않는다.
- `shift_reg_8bit`와 FIR가 같은 공통 경로를 사용하고 자기 설계로 바꾸는 절차가 설명되어 있다.
- 미지원·미검증·선택 항목과 코어 완료 이후 필요한 칩 수준 작업이 분명하다.

구체적인 릴리스 점검과 수행 범위·시점은 [ROADMAP.md](ROADMAP.md#3-최초-릴리스-체크리스트)에서 관리한다.
